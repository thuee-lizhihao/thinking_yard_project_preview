The core idea

Drop selected KV.
Reuse the rest.

Long agent histories make attention expensive. Trimming or summarizing old messages invalidates the cache that follows. Cache engineering lets agents remove selected KV entries and keep using the states already computed.

The serving design

The same tokens.
Different cache states.

Cache states depend on when earlier states were dropped or repositioned. Matching token prefixes alone is no longer enough. AKV tracks the operation history so agents can control the cache without managing its storage.

01 / REUSE

Match the full history.

An extended radix tree tracks tokens and cache operations together, so requests share only compatible states.

02 / EVICT

Free what is no longer needed.

Request isolation lets the server reclaim dropped KV when it is no longer needed for computation or restoration.

03 / RESTORE

Recover in one prefill pass.

Segment-batch attention reconstructs missing states using the visibility and positions from their original trajectory.

Beyond a fixed policy

Agents can learn
what to keep.

Rolling drop is a starting point. AKV also lets agents choose cache operations and search for better policies.

Search for a better policy.

MiniMax-M2.7 recursively refines its cache policy on BrowseComp-Plus, reaching a 17.8% cost reduction relative to Standard at iteration 6 while maintaining Standard’s accuracy.
